## 요구사항

### [ 목표 ]

- Jest와 Supertest를 사용해 유닛 테스트, 통합 테스트 작성하기

### [ 작업 내용 ]

### 1. 기본 요구사항

- [x] Jest의 테스트 커버리지 도구를 사용하도록 설정
- [x] publicProduct.test.ts : 인증이 필요하지 않은 상품 API에 대한 통합 테스트
- [x] publicArticle.test.ts : 인증이 필요하지 않은 게시글 API에 대한 통합 테스트
- [x] auth.test.ts : 로그인, 회원가입 API에 대한 통합 테스트
- [x] authProduct.test.ts : 인증이 필요한 상품 API에 대한 통합 테스트
- [x] authArticle.test.ts : 인증이 필요한 게시글 API에 대한 통합 테스트

### 2. 심화 요구사항

- [x] 상품 API의 비즈니스 로직에 대해 Mock, Spy를 활용해 유닛 테스트를 작성

## 멘토에게
- 요구사항에 "댓글"이나 "좋아요" 기능에 대한 부가 기능 테스트 언급이 없어서, 일단 기본 CRUD 기능에 대해서만 테스트를 작성했고 나머지 기능은 "개별 심화"로 주석처리 해 두었습니다. 
(다음 미션까지 하려고 목표 삼았는데, AWS가 너무 어려워서 장담 못드릴거 같아요 ㅎㅎㅎㅎㅎㅎㅎㅎ)
- 통합 테스트는 할만 했는데, 유닛 테스트는 어느 부분을 테스트 해야 할지 모르겠어서, AI의 도움을 전폭적으로 받아 진행 했습니다. 
- 테스트 파일 별로 하나씩 run test 할 때는 문제가 없었는데, 한번에 전체 테스트를 진행하니 병렬 실행되면서 동일한 DB에 동시에 접근했고 beforeAll / beforeEach가 동시 다발로 실행되면서 테스트용 데이터까지 초기화 하는 문제가 생겼습니다. 찾아보니 실무에서는 서로 영향을 주는 DB들을 분리해서 Test DB를 여러개 쓴다고 하던데, 바로 적용하는데에는 (제 개발 실력에)무리가 있는 것 같아서 일단 직렬 실행 되도록 "--runInBand"옵션을 사용하였습니다.  
(--maxWorkers=2 옵션도 충돌 발생했습니다..ㅎㅎ)
